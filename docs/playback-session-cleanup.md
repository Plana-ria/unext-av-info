# 要注意：再生関連APIのセッション終了処理

> **重要 / 変更時は必ず回帰検証**
>
> U-NEXTの `cosmo_getPlaylistUrl` を拡張機能が独自に呼び出すと、実際に動画を再生しなくても、同一作品の別端末での再生制限に影響するセッションが残ることがある。品質情報を正常取得できたことだけで完了扱いにしない。

## 確認された現象と解決（2026-11-02）

- **通常プレーヤー**：通常再生しタブを閉じる場合、および拡張機能ONのまま通常再生する場合は問題が再現しなかった。
- **作品詳細ページ**：拡張機能による再生関連APIの独自呼び出しで、別端末から同じ作品を再生すると制限に引っかかる現象が発生。
- **再生ページ**：独自照会後のセッション解放処理は正常に動作していた。
- **作品詳細ページの不具合原因**：API呼び出しのIDが `runId-attempt`（例：`1-0`, `1-1`）なのに、終了要求は `runId`（例：`1`）だった。完全一致だけでは対象セッションが見つからず、90秒後のフォールバックに依存していた。
- **解決確認**：`key === id || key.startsWith(id + '-')` の照合で各試行のセッションを解放するよう変更した後、ユーザーが作品ページでも正常動作したと確認した。

## 絶対に守る実装上の条件

1. **`cosmo_getPlaylistUrl` の拡張機能による呼び出し経路をすべて追跡すること。** 現状は作品詳細ページ（`UAI_QUERY`）と再生ページの最高品質照会（`UAI_PLAYBACK_QUERY`）。追加した経路も必ず終了管理の対象とする。
2. APIレスポンス `webfront_playlistUrl.playToken` と `urlInfo[].code`（`MEZ...`）を**そのリクエスト単位**で一時管理する。別のリクエストや通常プレーヤーのトークンを流用・停止しない。
3. **解析終了後に順番どおり** `interruption → stop` を送る。並列送信しない。前者が失敗しても後者は試行する。
4. 作品詳細ページでは**試行サフィックスを含むID照合**を維持すること。単純な完全一致に戻してはいけない。
5. 成功・失敗のどちらでも解析側の `finally` から終了を依頼する。ページ離脱や機能OFFなどの中断にもベストエフォートの停止処理を維持する。
6. トークンをログ、永続ストレージ、ユーザー向けエラーメッセージに出さない。通常再生中のセッションには触れない。
7. ネットワーク要求がサーバーに到達してから応答取得前に中断されるケース、停止通知自体の失敗、タブ終了時の処理は完全保証できない。終了通知が実行されたことと、サーバー側で解放されたことは区別する。

## 観測したAPI形式

```text
GET https://beacon.unext.jp/beacon/interruption/{MEZ}/{position}/?play_token={playToken}
GET https://beacon.unext.jp/beacon/stop/{MEZ}/{position}/?play_token={playToken}&last_viewing_flg=0
```

- 通常プレーヤーで**一時停止**した際に `interruption`、**×ボタンで終了**した際に `stop` を観測。
- 独自品質照会の後始末では `position=0` と `last_viewing_flg=0` を暫定採用している。これらのパラメータの正式な意味は未確認。
- 観測された `stop` のレスポンスはHTTP 200、JSON本文 `result.status = "200"`。ヘッダー `x-api-status-code: 404` も観測されており、ヘッダーだけで成功・失敗を断定しない。
- `interruption → stop` の2段階は実機での切り分けに基づく運用上の実装であり、U-NEXTの公開仕様として保証されたものではない。

## コード上の関連箇所

- `probe.js`：`registerProbeSession()`, `stopProbeSession()`, `UAI_RELEASE_PROBE_SESSION` と2つの `cosmo_getPlaylistUrl` 呼び出し。
- `content.js`：作品詳細ページの `run()` 完了時に終了を通知。**IDは基底runIdであり、試行IDとは異なる。**
- `playback-ui.js`：再生ページの `loadPlaylistHighest()` 完了時に終了を通知。
- 90秒フォールバックは緊急時の保険であり、通常の解放タイミングとして依存しない。

## 変更時の必須テスト

1. 作品詳細ページで再生関連APIを使う品質調査をONにし、解析完了後にNetworkで `interruption` → `stop` が送られるか確認する。
2. 同じ作品を**別端末で再生できること**を確認する。今回の問題の本来の受け入れ条件。
3. 再生ページの最高品質取得でも同様の確認をする（正常だった経路の退行防止）。
4. API失敗、再試行、途中の画面遷移、拡張機能OFFの各ケースで対象トークンの後始末と誤停止がないか確認する。
5. 未再生の作品が意図せず履歴に追加されたり、視聴位置が変わったりしないことを確認する。
